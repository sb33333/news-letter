# DevLetter 요구사항 도출 목록

- 문서 단계: 요구사항 분석
- 문서 상태: 검토 완료 초안
- 기준 버전: 2026-11-19
- 우선순위: `Must` / `Should` / `Could` / `미정`
- 요구사항 ID: `FR-{DOMAIN}-{번호}` 형식

## 1. 사용자 및 관리자 구분

### 1.1 시스템 사용자

- **사용자**: 비회원, 일반 회원
- **관리자**: 콘텐츠 관리자, 인프라 관리자

> 관리자 역할별 세부 권한은 설계 단계에서 확정한다.

## 2. 기능 요구사항

### 2.1 뉴스

#### FR-NEWS-001. 뉴스 목록 조회

- **요구사항 설명**: 사용자는 등록된 뉴스 목록을 조회할 수 있다.
- **상세 조건**
  - 수집된 뉴스는 페이지 단위로 조회한다.
  - 뉴스 목록은 발행일 내림차순으로 정렬한다.
  - 발행일이 동일한 경우 수집일시 내림차순으로 정렬한다.
  - 뉴스 목록에는 썸네일, 기사 제목, 발행일, 요약문을 표시한다.
- **우선순위**: 미정
- **검증 기준**
  - 등록된 뉴스가 있는 경우 뉴스 목록이 출력된다.
  - 뉴스 목록에 기사 제목, 발행일, 썸네일, 요약문이 출력된다.
  - 썸네일이 없는 뉴스는 기본 이미지가 출력된다.
  - 발행일이 동일한 경우 수집일시 내림차순으로 정렬된다.
  - 뉴스 목록이 페이지 단위로 조회된다.
  - 등록된 뉴스가 없는 경우 안내 메시지가 출력된다.
- **비고**: 없음

#### FR-NEWS-002. 뉴스 상세 조회

- **요구사항 설명**: 사용자는 등록된 뉴스의 상세 정보를 조회할 수 있다.
- **상세 조건**
  - 기사 제목, 발행일, 썸네일, 요약문을 출력한다.
  - 원문 URL 링크를 제공하여 원본 사이트로 이동할 수 있다.
  - RSS에서 제공되는 상세 콘텐츠가 있는 경우 이를 활용한다.
- **우선순위**: 미정
- **검증 기준**
  - 등록된 뉴스의 상세 정보를 정상적으로 조회할 수 있다.
  - 뉴스 제목, 발행일, 썸네일, 요약문이 정상 출력된다.
  - 원문 URL 링크를 클릭하면 해당 원문 사이트로 이동한다.
  - RSS에서 제공하는 상세 콘텐츠가 있는 경우 상세 콘텐츠가 출력된다.
  - 상세 콘텐츠가 없는 경우에도 뉴스 상세 화면을 정상적으로 조회할 수 있다.
  - 존재하지 않는 뉴스 ID로 접근하면 적절한 오류 화면이 출력된다.
- **비고**: 없음

#### FR-NEWS-003. 뉴스 목록 필터

- **요구사항 설명**: 사용자는 원하는 기준을 선택하여 뉴스 목록을 필터링할 수 있다.
- **상세 조건**
  - **뉴스 발행일 필터**: 뉴스 발행일을 기준으로 필터를 적용한다. 뉴스 목록 최초 진입 시 현재 날짜를 기준으로 1개월 전부터 현재까지의 뉴스 발행일 필터를 적용한다. 사용자가 뉴스 발행일 필터를 변경한 경우 변경된 조건을 적용한다.
  - **주제 필터**: 복수의 주제를 선택할 수 있다. 복수 주제 선택 시 OR 조건을 적용한다. 선택한 주제가 없으면 모든 주제의 뉴스를 표시한다.
  - 선택한 필터에 맞는 결과가 없으면 안내 메시지를 출력한다.
  - 필터 선택 상태는 사용자 환경(예: 브라우저)에 저장한다.
  - 페이지 새로고침 및 재방문 시 저장된 필터를 복원한다.
- **우선순위**: 미정
- **검증 기준**
  - 뉴스 발행일 필터 적용 시 발행일 조건에 맞는 뉴스만 출력한다.
  - 주제 필터 선택 시 선택한 주제에 맞는 뉴스만 출력한다. 복수 주제를 선택하는 경우 선택한 주제 중 하나 이상에 해당하는 뉴스가 출력된다.
  - 주제 필터를 선택하지 않는 경우 모든 주제의 뉴스가 출력된다.
  - 날짜 필터와 주제 필터를 함께 적용하는 경우 두 조건을 모두 만족하는 뉴스가 출력된다.
  - 필터 조건에 해당하는 뉴스가 없으면 안내 메시지가 출력된다.
  - 페이지를 새로고침해도 기존 필터 조건이 유지된다.
  - 브라우저를 재방문해도 저장된 필터 조건이 복원된다.
- **비고**
  - 필터 조건은 필요 시 보완한다.
  - 필터 저장 방식(Local Storage, Cookie 등)을 검토한다.
  - 필터 초기화 기능 도입 여부를 검토한다.
  - 존재하지 않는 주제 ID가 저장되어 있는 경우의 처리 방식을 결정한다.

#### FR-NEWS-004. 뉴스 관리

- **요구사항 설명**: 관리자는 수집된 뉴스 기사의 노출 여부를 관리한다.
- **상세 조건**
  - 관리자는 수집이 완료되어 데이터베이스에 저장된 뉴스 목록을 조회할 수 있다.
  - 수집된 뉴스 목록에는 뉴스 제목, 뉴스 수집일, 뉴스 공개 여부를 표시한다.
  - 수집된 뉴스 목록은 뉴스 수집일 내림차순으로 정렬한다.
  - 관리자는 수집된 뉴스의 노출 여부를 수정할 수 있다.
  - 비공개 설정된 뉴스 기사는 사용자 목록에 표시되지 않으며, 사용자는 상세 화면에 접근할 수 없다.
  - 뉴스 비공개 시 이미 등록된 댓글과 스크랩은 유지한다.
- **우선순위**: 미정
- **검증 기준**
  - 수집된 뉴스 목록이 정상적으로 출력된다.
  - 수집된 뉴스 목록이 수집일 내림차순으로 정렬된다.
  - 뉴스 기사의 노출 여부가 정상적으로 적용된다.
  - 사용자가 비공개 설정된 뉴스 기사 상세 화면에 접근하는 경우 차단된다.
  - 뉴스를 비공개 처리해도 댓글과 스크랩은 유지된다.
- **비고**: 없음

### 2.2 회원 및 인증

#### FR-MEMBER-001. 회원 가입

- **요구사항 설명**: 사용자는 이메일 주소와 비밀번호를 입력해 일반 회원으로 가입할 수 있다.
- **상세 조건**
  - 이메일 주소는 이메일 주소 형식에 맞아야 한다.
  - 중복된 이메일 주소로 가입할 수 없다.
  - 비밀번호 정책을 검증한다.
  - 비밀번호는 암호화된 형태로 저장한다.
  - 이메일 뉴스레터 수신 희망 여부를 선택할 수 있다.
- **우선순위**: 미정
- **검증 기준**
  - 올바른 이메일 주소와 비밀번호를 입력하면 회원 가입이 완료된다.
  - 올바른 형식의 이메일 주소가 아닌 경우 회원 가입이 실패한다.
  - 이미 가입된 이메일 주소인 경우 회원 가입이 실패한다.
  - 비밀번호 정책에 맞지 않는 비밀번호인 경우 회원 가입이 실패한다.
  - 비밀번호 값이 암호화된 형태로 저장된다.
  - 뉴스레터 수신 희망 여부가 선택한 값으로 저장된다.
- **비고**
  - 초기 버전에서는 이메일 인증 없이 가입이 완료되도록 한다.
  - 회원의 이메일 주소는 고유해야 한다.
  - 탈퇴한 회원이 이전과 동일한 이메일 주소로 재가입할 수 있도록 허용할지 검토한다. 재가입을 허용하는 경우 회원을 식별하기 위한 고유 키를 사용한다.

#### FR-AUTH-001. 로그인

- **요구사항 설명**: 등록된 회원은 이메일과 비밀번호를 사용해 로그인할 수 있다.
- **상세 조건**
  - 이메일과 비밀번호가 일치하면 로그인한다.
  - 비밀번호 오류가 5회 누적되면 5분간 로그인을 제한한다.
  - 5분의 로그인 잠금 시간이 경과해도 비밀번호 오류 횟수는 초기화하지 않는다.
  - 로그인이 성공하면 오류 횟수를 초기화하고 잠금을 해제한다.
  - 회원 로그인 성공 여부와 마지막 로그인 시도 일시를 데이터베이스에 저장한다.
- **우선순위**: 미정
- **검증 기준**
  - 올바른 이메일과 비밀번호를 입력하면 로그인에 성공한다.
  - 등록되지 않은 이메일을 입력하면 로그인에 실패한다.
  - 잘못된 비밀번호를 입력하면 로그인에 실패한다.
  - 비밀번호가 5회 연속 불일치하면 로그인이 차단된다.
  - 차단 상태에서 로그인을 시도하면 로그인 시도가 차단된다.
- **비고**: 없음

#### FR-MEMBER-002. 회원 정보 관리

- **요구사항 설명**: 일반 회원은 회원 정보 관리 메뉴를 통해 회원 정보를 수정할 수 있다.
- **상세 조건**
  - 회원은 비밀번호를 변경할 수 있으며, 회원 가입과 동일한 비밀번호 정책을 적용한다.
  - 회원은 현재 비밀번호와 동일한 비밀번호로 변경할 수 없다.
  - 회원은 뉴스레터 수신 여부를 변경할 수 있다.
- **우선순위**: 미정
- **검증 기준**
  - 로그인한 회원은 자신의 비밀번호를 변경할 수 있다.
  - 비밀번호 변경 시 현재 비밀번호가 일치해야 한다.
  - 비밀번호 정책에 맞지 않는 비밀번호로 변경하면 수정이 실패한다.
  - 기존 비밀번호와 동일한 비밀번호로 변경하면 수정이 실패한다.
  - 비밀번호 변경 후 새로운 비밀번호로 로그인할 수 있으며, 기존 비밀번호로는 로그인할 수 없다.
  - 회원은 다른 회원의 정보를 수정할 수 없다.
- **비고**: 없음

#### FR-AUTH-002. 로그아웃

- **요구사항 설명**: 로그인 상태의 일반 회원은 로그아웃할 수 있다.
- **상세 조건**
  - 로그아웃 시 뉴스 목록 화면으로 리다이렉트한다.
  - 브라우저 세션이 만료된 경우 로그아웃 상태가 된다.
- **우선순위**: 미정
- **검증 기준**
  - 로그아웃 요청 후 로그인 상태가 해제된다.
  - 로그아웃 후 뉴스 목록 화면으로 이동한다.
  - 로그아웃 후 인증이 필요한 기능에 접근할 수 없다.
  - 세션이 만료된 상태에서 보호된 기능에 접근하면 비로그인 상태로 처리된다.
- **비고**
  - 로그아웃 시 모든 브라우저 또는 사용자 접속을 해제할지 검토한다.

#### FR-MEMBER-003. 회원 탈퇴

- **요구사항 설명**: 회원은 회원 탈퇴를 할 수 있다.
- **상세 조건**
  - 회원 탈퇴 시 올바른 비밀번호를 입력해야 한다.
  - 회원 탈퇴 시 저장된 스크랩 정보를 삭제한다.
  - 회원 탈퇴 시 회원 정보를 삭제한다.
  - 회원 탈퇴 시 작성한 댓글은 삭제하지 않는다.
  - 탈퇴한 회원의 댓글은 작성자 표시를 '탈퇴한 회원'으로 한다. 데이터베이스에 저장된 작성자 정보는 유지한다.
  - 댓글의 내용과 작성 시각은 유지한다.
- **우선순위**: 미정
- **검증 기준**
  - 올바른 비밀번호를 입력하면 회원 탈퇴가 정상 처리된다.
  - 잘못된 비밀번호를 입력하면 회원 탈퇴가 실패한다.
  - 탈퇴 시 회원 정보가 삭제된다.
  - 탈퇴한 회원의 스크랩 정보는 삭제된다.
  - 탈퇴한 회원은 기존 계정으로 로그인할 수 없다.
  - 탈퇴한 회원의 세션이 무효화된다.
  - 탈퇴한 회원의 댓글은 정의된 정책에 따라 표시된다.
- **비고**: 없음

### 2.3 스크랩

#### FR-SCRAP-001. 스크랩 등록

- **요구사항 설명**: 로그인한 회원은 원하는 뉴스 기사를 스크랩할 수 있다.
- **상세 조건**
  - 회원은 뉴스 상세 또는 뉴스 목록에서 스크랩할 수 있다.
  - 회원은 동일한 뉴스를 중복 스크랩할 수 없다.
  - 회원은 비공개된 뉴스를 스크랩할 수 없다.
- **우선순위**: 미정
- **검증 기준**
  - 회원이 선택한 기사가 정상적으로 스크랩된다.
  - 중복된 기사를 스크랩 요청하면 중복 요청 안내 메시지를 반환한다.
  - 비공개된 뉴스를 스크랩 요청하면 불가능한 요청 안내 메시지를 반환한다.
  - 존재하지 않는 뉴스 ID로 스크랩 요청하면 불가능한 요청 안내 메시지를 반환한다.
  - 다른 회원의 스크랩 데이터에 영향을 주지 않는다.
- **비고**: 없음

#### FR-SCRAP-002. 스크랩 취소

- **요구사항 설명**: 로그인한 회원은 자신이 스크랩한 뉴스의 스크랩을 취소할 수 있다.
- **상세 조건**
  - 회원은 뉴스 상세 또는 뉴스 목록에서 스크랩을 취소할 수 있다.
  - 회원은 스크랩한 기사 목록에서 원하는 스크랩을 선택해 취소할 수 있다.
- **우선순위**: 미정
- **검증 기준**
  - 회원이 선택한 스크랩이 정상적으로 취소된다.
  - 스크랩 취소 후 해당 뉴스가 회원의 스크랩 목록에서 제거된다.
  - 다른 회원의 스크랩을 취소할 수 없다.
  - 이미 취소된 스크랩을 다시 취소해도 오류가 발생하지 않는다.
- **비고**: 없음

#### FR-SCRAP-003. 스크랩 관리

- **요구사항 설명**: 회원은 스크랩한 뉴스를 관리할 수 있다.
- **상세 조건**
  - 회원은 자신이 스크랩한 뉴스 목록을 조회할 수 있으며, 뉴스의 제목, 뉴스 발행일, 스크랩 등록일을 출력한다.
  - 스크랩한 기사 목록은 페이징 방식으로 출력한다.
  - 스크랩한 기사 목록은 정렬할 수 있으며, 기본 정렬 기준은 스크랩 등록일 내림차순, 기사 발행일 내림차순 순으로 한다.
  - 스크랩한 기사를 선택하면 뉴스 기사 상세 보기 화면으로 이동한다.
  - 회원은 스크랩한 기사 목록에서 원하는 스크랩을 선택해 취소할 수 있다.
  - 회원은 다른 회원의 스크랩 데이터에 접근할 수 없다.
  - 스크랩한 기사 중 비공개 상태로 변경된 뉴스는 스크랩 목록에는 출력되지만 상세 보기 화면으로 이동할 수 없다.
- **우선순위**: 미정
- **검증 기준**
  - 로그인한 회원은 자신이 스크랩한 뉴스 목록을 조회할 수 있다.
  - 스크랩한 뉴스의 제목, 발행일, 스크랩 등록일이 정상 출력된다.
  - 스크랩 목록은 페이지 단위로 조회된다.
  - 스크랩 목록은 스크랩 등록일 내림차순으로 정렬하고, 스크랩 등록일이 같은 경우 기사 발행일 내림차순으로 정렬한다.
  - 스크랩한 뉴스가 없는 경우 안내 메시지가 출력된다.
  - 회원은 다른 회원의 스크랩 목록에 접근할 수 없다.
  - 스크랩을 취소하는 경우 목록에서 제거된다.
- **비고**
  - 뉴스가 삭제되거나 비공개 처리되는 경우 기존 스크랩을 어떻게 처리할지 검토한다. 비공개 처리 시 목록에 유지하고 상세 화면 접근을 제한한다는 조건은 상세 조건에 정의되어 있다.

### 2.4 RSS 수집

#### FR-RSS-001. RSS 출처 관리

- **요구사항 설명**: 관리자는 뉴스 수집을 위한 RSS 출처를 등록하고 관리할 수 있다.
- **상세 조건**
  - 관리자는 RSS URL을 등록할 수 있다.
  - RSS URL 등록 시 URL 형식 유효성을 검증한다.
  - RSS URL 등록 시 기본 뉴스 주제를 지정한다.
  - 관리자는 등록된 RSS 출처 목록을 조회할 수 있다.
  - 등록된 RSS 출처 목록에는 등록일, 수집된 기사 개수, 활성화 여부를 표시한다.
  - 관리자는 RSS 출처 활성화 여부를 수정할 수 있다. 비활성화된 RSS 출처에서는 뉴스를 더 이상 수집하지 않는다.
  - 관리자는 RSS 출처를 삭제할 수 있다.
- **우선순위**: 미정
- **검증 기준**
  - 유효한 RSS URL과 뉴스 주제를 입력하면 RSS 출처가 등록된다.
  - RSS URL 형식이 유효하지 않은 경우 등록이 실패한다.
  - 등록된 RSS 출처가 RSS 출처 목록에 정상적으로 조회된다.
  - 등록 시 지정한 뉴스 주제가 정상적으로 연결된다.
  - 등록되고 활성화된 RSS 출처에서 뉴스가 수집되는지 확인한다.
- **비고**: RSS URL 등록 시 실제 접속 가능 여부를 검증할지는 검토 대상에서 제외한다.

#### FR-RSS-002. RSS 뉴스 정보 수집

- **요구사항 설명**: 시스템은 활성화된 RSS 출처에서 정해진 주기에 따라 뉴스 정보를 자동으로 수집하고 저장한다.
- **상세 조건**
  - 활성화된 RSS 출처를 대상으로 수집한다.
  - RSS 출처에서 뉴스 정보를 추출하고 데이터베이스에 저장한다.
  - 뉴스의 중복 여부를 원문 URL로 판단한다.
  - 중복된 기사 정보는 저장하지 않는다.
  - RSS 출처별 수집 결과를 기록한다. 뉴스 수집 성공·실패 여부를 저장하고, 실패 시 실패 원인을 기록한다(연결 실패, 소스 파싱 실패 등).
  - 특정 RSS 출처에서 정보 수집이 실패하더라도 나머지 출처의 정보 수집은 계속 진행할 수 있어야 한다.
  - RSS 출처에서 정보 수집이 실패한 경우 이번 수집에서는 재시도하지 않고 다음 수집에서 다시 시도한다.
  - 뉴스 수집 주기를 관리자가 설정할 수 있다. 뉴스 수집 주기는 모든 RSS 출처에 동일하게 적용한다.
- **우선순위**: 미정
- **검증 기준**
  - 활성화된 RSS 출처의 뉴스 정보가 정상적으로 수집된다.
  - 비활성화된 RSS 출처에서는 뉴스 정보가 수집되지 않는다.
  - 수집된 뉴스 정보가 데이터베이스에 저장된다.
  - 동일한 원문 URL을 가진 뉴스는 중복 저장되지 않는다.
  - RSS 출처별 수집 성공 여부가 기록된다.
  - RSS 수집 실패 시 실패 원인이 기록된다.
  - 특정 RSS 출처에서 수집이 실패해도 다른 RSS 출처의 수집은 계속 진행된다.
  - 수집에 실패한 RSS 출처는 다음 수집 주기에 다시 수집을 시도한다.
  - 관리자가 설정한 수집 주기에 따라 수집 작업이 실행된다.
- **비고**: RSS 출처별로 수집 주기를 지정하는 기능의 도입을 검토한다.

### 2.5 뉴스레터

#### FR-LETTER-001. 뉴스레터 발송

- **요구사항 설명**: 시스템은 뉴스레터 수신을 희망하는 회원에게 주기적으로 뉴스레터 메일을 발송한다.
- **상세 조건**
  - 뉴스레터 수신을 희망하는 회원에게 발송한다.
  - 뉴스레터 발송은 주 1회 실시한다.
  - 뉴스레터 내용은 최근 뉴스 기사 10개를 선정한다.
  - 뉴스레터 발송 후 발송 성공 여부를 기록한다.
  - 특정 회원에게 발송이 실패해도 다른 회원에 대한 발송은 계속 진행된다.
  - 특정 회원에게 뉴스레터 발송이 실패한 경우 재시도하지 않는다. 다음 뉴스레터 발송 시에는 발송을 시도한다.
- **우선순위**: Must
- **검증 기준**
  - 뉴스레터 수신을 희망하는 회원에게만 뉴스레터가 발송된다.
  - 뉴스레터 수신을 거부한 회원에게는 뉴스레터가 발송되지 않는다.
  - 정해진 주기에 뉴스레터가 발송된다.
  - 뉴스레터 내용으로 최근 뉴스 10개가 선정된다.
  - 뉴스레터에 포함된 기사 정보와 원문 URL이 정상 출력된다.
  - 뉴스레터 발송 성공 및 실패 결과가 기록된다.
  - 특정 회원에게 발송이 실패하더라도 다른 회원에 대한 발송은 진행된다.
- **비고**
  - 뉴스레터 발송 주기를 관리자가 설정할 수 있는 기능의 도입을 검토한다.
  - 삭제되거나 비공개 처리된 뉴스의 처리 방식을 결정한다.

#### FR-LETTER-002. 뉴스레터 수신 관리

- **요구사항 설명**: 일반 회원은 뉴스레터 수신 여부를 변경할 수 있다.
- **상세 조건**
  - 회원 정보 수정 메뉴에서 뉴스레터 수신 여부를 변경한다.
  - 뉴스레터 내용에 수신 거부 링크를 포함한다.
- **우선순위**: 미정
- **검증 기준**
  - 뉴스레터 수신 여부를 활성화하면 회원의 수신 상태가 변경된다.
  - 뉴스레터 수신 여부를 비활성화하면 회원의 수신 상태가 변경된다.
  - 뉴스레터에 포함된 수신 거부 링크로 접근하면 해당 회원의 뉴스레터 수신 여부가 비활성화된다.
  - 회원은 다른 회원의 뉴스레터 수신 여부를 조회하거나 변경할 수 없다.
- **비고**: 수신 거부 링크의 구체적인 구현 방식을 검토한다.

### 2.6 댓글

#### FR-COMMENT-001. 댓글 조회

- **요구사항 설명**: 사용자는 뉴스 기사에 연결된 댓글을 조회할 수 있다.
- **상세 조건**
  - 뉴스 상세 화면에 해당 기사에 연결된 댓글을 출력한다.
  - 댓글은 작성일시 내림차순으로 정렬한다.
  - 하위 댓글은 상위 댓글의 자식 목록으로 출력한다.
  - 최상위 댓글을 페이징으로 출력한다.
  - 하위 댓글은 2개 이상일 경우 첫 번째 하위 댓글만 표시하며, 나머지 하위 댓글은 '더 보기'를 눌렀을 때 출력한다.
  - 삭제된 댓글은 목록에 '삭제된 의견입니다.'라는 문구로 표시한다.
  - 비공개 처리된 댓글은 목록에 '비공개된 의견입니다.'라는 문구로 표시한다.
- **우선순위**: 미정
- **검증 기준**
  - 다른 뉴스 기사에 등록된 댓글은 출력되지 않는다.
  - 댓글이 작성일시 내림차순으로 정렬된다.
  - 하위 댓글은 해당 상위 댓글의 자식 목록으로 출력된다.
  - 최상위 댓글이 페이징으로 출력된다.
  - 하위 댓글이 2개 이상인 경우 '더 보기' 표시가 출력된다.
  - '더 보기'를 누르면 하위 댓글이 5개 단위로 출력된다.
  - 삭제된 댓글의 내용은 표시되지 않는다.
  - 비공개 처리된 댓글의 내용은 표시되지 않는다.
- **비고**: 없음

#### FR-COMMENT-002. 댓글 등록

- **요구사항 설명**: 로그인한 일반 회원은 뉴스 기사에 댓글을 작성할 수 있다.
- **상세 조건**
  - 댓글은 300자 이내로 작성할 수 있다.
  - 댓글은 해당 뉴스 기사 상세 화면에 출력된다.
  - 다른 댓글의 하위 댓글로 작성할 수 있다.
- **우선순위**: 미정
- **검증 기준**
  - 로그인한 회원이 작성한 댓글이 정상 등록된다.
  - 300자 길이 제한을 초과하는 경우 등록되지 않는다.
  - 공백만 입력한 경우 댓글이 등록되지 않는다.
  - 로그인하지 않은 사용자는 댓글을 등록할 수 없다.
  - 하위 댓글은 지정한 상위 댓글에 연결되어 등록된다.
- **비고**
  - 댓글 수정 이력 또는 변경 이력을 저장할 필요가 있는지 검토한다. 필요하다면 댓글 이력을 관리하는 별도 테이블 등의 방식을 설계 단계에서 검토한다.

#### FR-COMMENT-003. 댓글 수정

- **요구사항 설명**: 로그인한 회원은 자신이 작성한 댓글을 수정할 수 있다.
- **상세 조건**
  - 회원은 자신이 작성한 댓글을 수정할 수 있다.
  - 회원은 다른 회원이 작성한 댓글을 수정할 수 없다.
  - 수정된 댓글에는 '(수정됨)' 표시를 출력한다.
- **우선순위**: 미정
- **검증 기준**
  - 다른 회원이 작성한 댓글을 수정하는 경우 요청이 실패한다.
  - 댓글 수정 내용이 300자를 초과하는 경우 요청이 실패한다.
  - 수정된 댓글에 '(수정됨)' 표시가 출력된다.
- **비고**: 없음

#### FR-COMMENT-004. 댓글 삭제

- **요구사항 설명**: 로그인한 회원은 자신이 작성한 댓글을 삭제할 수 있다.
- **상세 조건**
  - 회원은 자신이 작성한 댓글을 삭제할 수 있다.
  - 회원은 다른 회원이 작성한 댓글을 삭제할 수 없다.
- **우선순위**: 미정
- **검증 기준**
  - 다른 회원이 작성한 댓글을 삭제할 수 없다.
  - 삭제된 댓글은 수정할 수 없다.
  - 상위 댓글이 삭제되어도 하위 댓글은 삭제되지 않는다.
- **비고**: 없음

#### FR-COMMENT-005. 댓글 관리

- **요구사항 설명**: 관리자는 뉴스 기사에 작성된 회원 댓글을 비공개 처리할 수 있다.
- **상세 조건**
  - 관리자는 기사에 작성된 댓글을 비공개 처리할 수 있다.
  - 비공개 처리 시 선택사항으로 비공개 사유를 입력할 수 있다.
  - 관리자는 비공개 처리한 댓글 현황을 조회할 수 있다. 비공개 처리일, 작성자 정보, 비공개 처리 사유를 제공한다.
  - 비공개 댓글 목록은 페이징으로 출력한다.
  - 비공개 댓글 목록은 비공개 처리일 내림차순으로 정렬한다.
  - 비공개 댓글 목록은 비공개 처리일을 기준으로 필터링할 수 있다. 기본 필터 값은 전체 기간이다.
  - 비공개 댓글 목록은 댓글 내용이나 비공개 처리 사유 내용으로 텍스트 필터링할 수 있다.
- **우선순위**: 미정
- **검증 기준**
  - 댓글을 비공개 처리하면 해당 댓글이 비공개 처리된다.
  - 비공개 댓글 목록에 비공개 처리일, 작성자 정보, 비공개 처리 사유가 출력된다.
  - 비공개 처리된 댓글은 댓글 조회 정책에 따라 출력된다.
  - 비공개 댓글 목록이 페이징으로 출력된다.
  - 비공개 댓글 목록이 비공개 처리일 내림차순으로 정렬된다.
  - 비공개 댓글 목록을 비공개 처리일 기준으로 필터링할 수 있다.
  - 비공개 댓글 목록을 댓글 내용이나 비공개 처리 사유 내용으로 필터링할 수 있다.
  - 비공개 처리일 필터와 내용 필터를 함께 적용하면 두 조건을 모두 만족하는 결과가 출력된다.
  - 비공개 처리된 댓글이 없는 경우 안내 메시지가 출력된다.
  - 검색 조건에 맞는 비공개 댓글이 없는 경우 안내 메시지가 출력된다.
- **비고**: 없음

### 2.7 관리자 기능

#### FR-ADMIN-001. 관리자 권한 및 메뉴 관리

- **요구사항 설명**: 관리자는 관리자 권한에 따라 허용된 관리 메뉴를 이용할 수 있다.
- **상세 조건**
  - 회원 현황을 조회할 수 있는 메뉴를 제공한다.
  - RSS 출처 관리를 할 수 있는 메뉴를 제공한다.
  - RSS 뉴스 수집 현황을 조회할 수 있는 메뉴를 제공한다.
  - 비공개 댓글 목록을 조회할 수 있는 메뉴를 제공한다.
- **우선순위**: 미정
- **검증 기준**
  - 관리자 계정으로 로그인하면 허용된 관리자 메뉴에 접근할 수 있다.
  - 일반 회원은 관리자 메뉴에 접근할 수 없다.
  - 관리자 권한이 없는 사용자는 관리자 기능의 API에 직접 접근할 수 없다.
- **비고**: 콘텐츠 관리자와 인프라 관리자 등 관리자 역할별 세부 권한을 설계 단계에서 구분한다.

## 3. 다음 단계에서 확정할 사항

아래 항목은 현재 요구사항을 무효화하는 누락 사항이라기보다, 유스케이스·도메인 모델·상세 설계를 진행하면서 구체화할 정책이다.

## 4. 요구사항 작성 및 관리 원칙

1. 요구사항은 기능 단위로 식별할 수 있도록 고유 ID를 부여한다.
2. 요구사항의 상세 조건은 구현할 동작과 정책을 기술한다.
3. 검증 기준은 요구사항 충족 여부를 확인할 수 있는 관찰 가능한 결과로 작성한다.
4. 아직 결정하지 않은 정책은 임의로 확정하지 않고 비고에 기록한다.
5. 구현 및 테스트 단계에서 요구사항이 변경되면 관련 ID를 유지하고 변경 이력을 관리한다.
6. 요구사항별 우선순위는 MVP 범위를 기준으로 별도 결정한다.
